# Anti-slop

压住模型腔，靠两处分工：

- **正向规则** `rules.md`：同步进 `~/.claude/CLAUDE.md` 的标记块，每轮常驻。只写要怎样表达，配改好后的例句。被否定的写法一旦写进常驻上下文，就会像粉色大象一样更容易出现，所以它们从不进这个文件。
- **度量清单** `patterns.json`：按功能分组，每组有原因、改法和若干正则变体。`hooks/measure.py` 在每次回复和写 Markdown 文件后计数写日志，只度量、不反馈，用来判断正向规则是否起效。

本目录下的路径都相对于 skill 所在目录。调用时按参数走分支：原句和改法 → 反馈；`report` → 报告；`install` / `uninstall` → 安装或卸载。

## 反馈

1. **取材料。** 从参数或当前对话拿到被否定的原句，以及改后版本或不喜欢的原因。两者都没有时，请用户补一个，别自己猜。
2. **归功能。** 判断原句在"做"什么，例如借对照制造分量、用金句收尾、把平常结论说成反直觉。符合 `patterns.json` 已有组的 `reason`，就归入该组。都不符合时，拟一个新组（`id`、`name`、`reason`、`fix`），请用户确认。
3. **负向入清单。** 能用正则抓住的字面结构，加进对应组的 `patterns`。用 `python3 hooks/measure.py test "<原句>"` 确认能命中；如有改后句，确认改后句不命中。再跑 `python3 hooks/measure.py baseline 30`，给用户看新条目的命中数，并挑几条命中样本，指出其中哪些是误报。只能靠语义判断的写法（例如收尾金句）不加正则，在回复里注明"仅由规则覆盖"。
4. **正向入规则。** 找到 `rules.md` 里对应的规则，把改后句作为"例："放在规则下面，每条规则最多两例，超出时换掉代表性较弱的那句。没有规则能覆盖时，按"情境 → 怎样表达"起草一条新规则，请用户认可措辞后再写入。写完后运行 `python3 hooks/measure.py test "$(cat rules.md)"`，结果必须为零命中。
5. **同步。** 运行 `./install.sh`，把新规则写入 `CLAUDE.md`。告诉用户新会话才会生效。

完成条件：原句被某个正则命中，或已明确标注"仅由规则覆盖"；`rules.md` 零命中；`install.sh` 已重跑；回复里列出新增或修改了哪些条目，以及基线命中数。

## 报告

运行 `python3 hooks/measure.py report [天数]`。解读时对比 `baseline` 同期的每千字次数，说明规则改动前后的变化。命中样本里真在纠错的句子要单独指出，作为误报，不计入"规则失效"。某组在规则生效后仍明显高于基线时，向用户建议两条路：补充例句，或把该组升级为拦截反馈。升级要用户决定。

## 安装与卸载

- `./install.sh`：同步规则块，注册 Stop 和 PostToolUse(Write|Edit) 两个度量 hook。重复运行结果不变。
- `./install.sh --uninstall`：删除规则块和所有命令里带 `anti-slop/hooks/` 的 hook，修改前把 `settings.json` 备份为 `.bak`。
- 加 `--purge` 会同时删除日志目录 `~/.claude/anti-slop`。

hook 命令在脚本文件缺失时静默跳过，所以没卸载就先删了目录，也不会每轮报错。
