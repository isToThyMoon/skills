# 测试审计

第 8 步读。目标：测试只留下值得它的构建和等待时间的那部分，日常检查快到 agent 愿意频繁运行。

LLM 写的项目常见测试比功能代码还多，还有很多防不到真实错误。有 AI coding 时，多数问题发现后很快能修好，所以一个测试要能回答：**它防的是哪种真实可能发生的错误？这种错误出现后，等发现了再修为什么来不及？** 答不上来就删。

## 判定标准

**留下**，至少满足一条：

1. 出错后果难挽回：资金和计费、数据丢失或迁移、鉴权和权限、安全。
2. 守外部契约：对接的协议、序列化格式、公开 API，这些出错时本地编译发现不了。假对端的数据要来自真实样本或对方文档，否则它守的只是我们自己的理解。
3. 复杂的纯逻辑：看代码判断不出对错的算法、状态机、并发调度。只断言常量取值的不算。
4. 同类 bug 真实发生过且反复出现。依据看修复类提交、测试注释和问题记录；查不到依据时，这条不作为留下的理由。
5. 一条主流程冒烟：证明应用还能跑起来。每个应用留一条就够。
6. 记录外部事实的决策表：取值来自外部规范、兼容性或实际踩过的坑，从代码里看不出原因。取值只是内部选择的不算。

**删除**，命中任一条：

- 复述实现：断言常量、默认值、getter、枚举，或把实现再写一遍。
- 测框架和语言本身的行为。
- mock 掉了被测逻辑，只验证调用过某个方法。
- 同一行为在不同层重复测，或多组参数走同一条路径。留最有价值的一个，能用表驱动合并的就合并。算重复要走同一条实现路径，留下的覆盖不能更窄。因重复而删时写明留下的是哪一个，它自己的结论必须是"留"，否则几个测试会互相引用后一起被删。
- 快照和界面结构断言，没人会真看它们的 diff。
- 长期跳过或偶发失败的。
- 只为覆盖率写的，以及只服务于已删测试的 helper 和 fixture。

基准和测量脚本不算测试：还在用的移出默认测试目标，不再用的删除。

拿不准时按删除处理，除非它沾上第 1 条。和项目文档冲突时，文档明确点名要保留的测试先留下，并在报告里列出，由用户决定是否修改那条规则；文档只是泛泛要求多写测试的，按上面的标准判定。

## 步骤

1. **基线。** 运行 `python3 <skill 目录>/scripts/test_inventory.py <repo> --list`，把输出存进 `$TMPDIR/setup-harness/tests.md`。在删除前串行跑一次现有的完整测试，记下耗时和失败，命中构建缓存的耗时不算数。构建要超过 10 分钟时先跳过全量，只记录原因。
2. **审计。** 把测试文件按主题分组，同一主题放进一组，跨文件的重复才看得出来；不超过 8 组，小项目就一组。测试超过约 1 万行时，先告诉用户分组数和预计成本（粗略按每千行测试 2.5 万 token 估算，不含执行删除），用户同意后再审。每组在全新上下文里启动一个不改仓库的子 agent（不支持子 agent 的工具就分批自己读）。prompt 里给它：上面的判定标准全文、这组的文件列表、产品一句话和第 2 步记下的出错代价最高的地方，要求它不跑构建，先看用例名和断言，有删除嫌疑的再读全文和被测代码，为每个文件写 `留 / 删 / 部分删`、一句引用标准的理由，以及读到了什么程度，只写 `$TMPDIR/setup-harness/tests-<组名>.md` 这一个文件。
3. **删减。** 先抽查每组至少三条删除结论，回到代码确认理由成立，并跨组核对因重复而删的测试，它们引用的对象都判为"留"；同一规则有多份实现时，比对各份的结论。抽查发现错误时，让这一组按错误类型复审。然后执行审计结论，清掉随之失效的 helper 和 fixture。用脚本批量删除时，逐文件对照 `HEAD`，确认消失的用例都在删除名单内，因为多删往往照样能编译。生产代码保持原样；只被测试用到的生产代码列进报告。审计发现第 1 条范围内的测试缺口时，这次不补，写进报告由用户决定。
4. **改流程。** 把配置里的覆盖率门槛和固定测试数量门槛改掉，CI 和 pre-commit 里的测试步骤同步精简，只保留快速检查和留下的测试。lint、安全、部署等其他步骤保持原样。
5. **核对门槛。** 审计中发现 `AGENTS.md` "测试"一节漏了值得守住的地方时补上，再按实际保留的测试更新检查入口的目标。
6. **验证。** 只跑受影响的测试目标，修掉删除带来的编译错误。修不好的恢复对应文件，并写进报告。默认检查出现基线里没有的失败时，写进报告。

## 完成条件

- `tests.md` 里每个测试文件都有结论。
- 删除的测试文件、断言或用例都能对应到一条删除标准，留下的都能对应到一条留下标准。
- 抽查结果已记进 `plan.md`，因重复而删的测试，引用的对象都判为"留"。
- 项目的配置和 CI 里不再有覆盖率门槛或固定测试数量门槛，除非用户明确要求保留。
- 再运行一次 `test_inventory.py`，精简前后的文件数、行数、比例和默认检查耗时都记进 `plan.md`。
- 受影响的测试目标能编译并通过，或失败已确认在铺设前就存在。
