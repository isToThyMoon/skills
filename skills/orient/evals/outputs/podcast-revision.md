# 第 8 类与案例修订片段

## 8. Standards / frameworks

先区分三种性质：**正式标准**由明确机构发布，规定共同技术或测量方法；**平台要求／指南**只约束对应平台或提供推荐做法；**制作方法**帮助团队组织工作，但未必有单一权威版本。以下不把本回答自行归纳的检查顺序冒充业内命名框架。

### 正式标准与行业规范

- **RSS 2.0 与播客扩展命名空间**：RSS 2.0 是开放分发的基础格式，节目与单集通过 channel、item、enclosure 等元素被读取；Apple 的 `itunes:` 标签和 Podcast Namespace 的 `podcast:` 标签可补充播客专用信息。具体扩展的支持度取决于平台。
- **ITU-R BS.1770**：ITU 发布的节目响度与 True Peak 测量建议，解决“不同工具如何用可比方式测量响度”的问题。它定义测量方法，不替所有平台规定统一目标值。
- **IAB Tech Lab Podcast Measurement Guidelines**：IAB Tech Lab 发布的播客下载、受众与广告投放测量规范，主要解决服务器日志口径不一致的问题；它不是内容质量评分框架。当前正式页面列出 v2.2（2024 年 5 月），v2.3 于 2026 年 7 月发布的是公开征求意见稿。[IAB 指南](https://iabtechlab.com/standards/podcast-measurement-guidelines/) [v2.3 公告](https://iabtechlab.com/press-releases/iab-tech-lab-releases-podcast-technical-measurement-guidelines-v2-3/)
- **WCAG 与 W3C WAI 媒体无障碍指南**：W3C 的无障碍标准与实施指导。对预录纯音频提供文字替代，解决无法获取声音的用户如何获得等价内容；转录应包含必要的说话人和非语言声音信息。[W3C 转录指南](https://www.w3.org/WAI/media/av/transcripts/)

### 平台要求与推荐指南

- **Apple Podcasts RSS 要求**：Apple 的平台接入规则，要求 feed 可公开访问、符合 RSS 2.0，并包含必要标签、至少一集、封面；单集需要稳定 GUID 及带 URL、长度、类型的 enclosure。它决定能否被 Apple 正确处理，不是全球通行法律。[Apple RSS 要求](https://podcasters.apple.com/support/823-podcast-requirements)
- **Apple 音频指南**：Apple 对 RSS 音频接受 MP3 或 AAC，并给出码率、响度和 True Peak 建议，用来平衡兼容性、带宽、清晰度与失真风险。约 -16 dB LKFS（±1 dB）和不高于 -1 dBFS True Peak 是 Apple 建议，不应表述成所有平台的强制标准。[Apple 音频要求](https://podcasters.apple.com/support/893-audio-requirements)
- **版权、人格权、隐私和广告披露规则**：这是法律／监管层而非单一播客框架，适用规则随司法辖区和发布方式变化。音乐许可、档案音频、嘉宾同意、敏感信息和赞助披露都应按实际地区核查。

### 实务方法（非统一命名标准）

- **编辑章程／format bible**：业内常见的项目文档类型，用来记录目标受众、节目承诺、栏目结构、语气和编辑边界；具体模板由团队自行制定。
- **阶段性质量门（quality gates）**：通用生产管理做法，在立项、录音前、粗剪和发布前分别检查不同风险，减少把所有问题拖到最终 QC。这里是方法类别，不指向某个播客行业认证框架。
- **本地图的教学检查法**：可依次问“服务谁、承诺什么、采用何种形式”，并在单集剪辑时检查每段是否提出问题、提供证据、推进理解或兑现承诺。这两组问句是本回答为了帮助初学者串联地图而做的归纳，**不是声称存在名为 Audience–Promise–Format 或‘问题—证据—推进—回报’的权威业内框架**。

## 案例中相关句子的修订

假设做一档“普通人怎样转行”的双周访谈节目：先确定目标听众，并用本地图的三个教学检查问题——“服务谁、持续承诺什么、哪种节目形式最适合兑现承诺”——明确节目不做泛励志故事，而是拆解决策、成本与失败。这里的三个问题是本回答的组织方式，不是引用某个有发布方的正式框架。

制作人随后产出 episode brief、研究档案和采访提纲；双方本地录音并取得授权；剪辑时可按人物的“原处境—触发点—尝试—代价—结果—可迁移经验”组织 rough cut。这个顺序只是该示例的叙事方案，不是所有转行访谈都必须遵守的行业标准。之后完成混音与 QC，由托管服务更新 RSS；发布后结合固定时间窗内的下载、分段留存、关注转化和听众来信复盘。若下载低，应分别验证触达不足、包装不清等候选原因；若点开后迅速离开，再重点检查开场兑现和内容结构，不能把症状直接当成单一原因。
