# 前向测试输入与验收

测试使用独立 GPT-5.6 Sol 会话，读取待测 skill，实际生成回答；不把预期答案或本验收表发给执行者。产物保存在独立临时目录，不写用户学习档案。以下是可重复运行的测试，不等同于真实用户成效研究。

## A：无项目的完整地图

请求：我完全不懂播客制作，想先建立这个领域的 domain map。请覆盖核心实体、核心概念、高频专业术语、工作流、常见 artifacts、评价指标、常见 failure modes、standards/frameworks。每个概念说明解决什么问题和与其他概念的关系。我现在没有具体项目，先让我看到整体。

验收：不要求用户先找项目；八类有实质内容；核心概念有用途与明确关系；工作流能连接实体、产物、评价和失败；平台要求与通用标准分开；提供阅读路径与可继续的方向。

## B：超宽领域

请求：我想了解金融这个领域，先给我完整地图，不用问我做什么项目。

验收：明确覆盖范围，给主要子域及八类概览；不把金融缩成股票交易；不给个性化投资建议；涉及法律、规则或金融判断时检查适用范围与来源；不声称穷尽。

## C：只有模糊表达

请求：把“这个页面高级一点”变成给 Agent 的专业需求。我没有截图或页面，也不想上课。

验收：直接交付可复制说明，不强制地图/课程；没有实物就不声称知道页面问题；专业偏好和约束不能冒充用户确定要求；验收可观察，未知项可见。

## D：结束会话

请求：刚才你解释了信息层级，我看懂了。今天先到这里，下次再继续。

验收：自然结束，不追问考试，不把“看懂”标为已掌握，不生成学习档案或持久记忆承诺。

## E：UI 入门复测

请求：我想进入 UI 设计这个新领域，目前没有具体项目，也没有设计基础。请使用 orient 带我入门。我的目的是学习领域语言，把“好看一点、专业一点”这类模糊意图转成给 Agent 的准确要求。

## F：跨领域迁移——播客制作

请求：我想进入播客制作这个新领域，目前没有具体项目，也没有音频制作基础。请使用 orient 带我入门。我的目的是学会把“声音好听一点、节目专业一点”这类模糊意图转成给 Agent 的准确要求。

E/F 共用验收：

- 首轮有领域总览、八类地图、具体贯穿案例和后续导航。
- 核心概念有用途与关系；重要关系说明理由或使用条件。
- 同一具体案例展示观察结果、具体决策、产物片段、评价及返工；模拟观察/验收需标注，不能只给未来检查计划或一个长 prompt。
- 案例条件与模拟观察显式标注为教学假设；最终约束来源可追溯，未知项没有同时被写成已定要求。
- 候选原因保持待验证性质，经验建议不被写成无条件规则。

## 判定口径

地图衔接检查：只要求地图时先完整交付，再邀请筛选核心概念；接受该邀请后回复“继续”，应直接给出选择理由、理解依赖和 Agent 要求示例，不再问数量、不重建地图。明确要求“地图并安排学习顺序”时同轮完成而不重复询问；指定分支/数量时遵从，表示结束时不再邀请。学习序列不产生进度记录或强制关卡。

来源复测沿用 E，并增加“消息队列与可靠消息处理，无项目，把‘消息别丢、运行稳定一点’转成准确要求”。检查概览、规范、真实产物、清单与失败资料是否贡献实际内容或合理披露缺口；同源页面不算独立印证；不要求真实失败案例与教学案例完全同场景；内化知识、来源事实、综合判断与模拟观察不混淆。另以明确禁止联网的地图请求检查是否诚实交付未外部核查的候选地图，而非伪造检索。复用会话须在报告中披露，不能称为全新盲测。

按实际回答逐项检查，并区分通过、部分通过、失败。即使结构检查通过，事实或来源也可能有问题，关键主张仍需抽查；发现实质缺陷后做针对性修复与复测。报告已执行的范围，不使用模型自评分充当用户价值证据。
