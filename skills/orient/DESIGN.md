# 从领域地图获得领域语言：方法与使用流程

## 设计目标

学习领域语言的核心目的：把模糊意图压缩成可执行约束，使用户能够准确向 Agent 表达要求，并依据明确标准判断结果。

为此，先回答“我还应该知道哪些东西”，再回答“这些东西如何工作、如何帮助我表达要求”。领域地图是入口和导航，实际案例是理解关系的方法，任务说明与验收是应用出口。用户无需先有项目，也无需接受学习状态追踪。

本设计根据用户明确偏好，以八类全景 domain map 为中心，不沿用旧版的基础闯关、强制少量词汇、常驻纠偏或掌握度档案。

八类决定内容覆盖，五层（Vocabulary、Concept、Relations、Workflow、Evaluation）决定理解与使用的组织方式。地图同时呈现名称、用途、关系、工作过程和判断依据，详细机制按需展开；五层不是学习等级，也不产生用户进度记录。具体交付要求以 [SKILL.md](SKILL.md) 为准。

## 对原论述的审视

原文有价值的判断是：词汇应连到概念、关系、工作流和评价；专业产物和失败案例有助于看见真实工作；模糊感觉可以转成更清晰的问题。八类地图同时提供广度和查漏能力，特别适合不知道该问什么的初学者。

需要修正的部分：

1. **术语不是质量保证。** “降低信息密度”可能仍然模糊，也可能误删任务所需内容。具体目标、实物、约束和验收证据才使要求可操作。专业词是压缩表达与检索入口，其收益不能与增加这些信息的收益混为一谈。
2. **地图不等于术语分类表。** 八个栏目下堆名词仍然难以使用。每项要说用途，并通过产生、依赖、约束、测量等关系连接其他项。相同对象跨类出现时交叉引用，不重复灌输。
3. **工作流不总是单向，概念不总能排成 DAG。** 用知识网络表示关联，用阅读路径处理教学顺序。不同流派和子领域可以有不同路线。
4. **“前 30 个词”和“一小时掌握”不是可靠通用标准。** 一小时可以得到有边界的地图并试用一个场景，不能据此认定拥有专家判断力。
5. **来源没有统一排行榜。** 标准适合查定义和约束；真实产物适合查工作方式；复盘适合查失败；研究和实测适合查效果。各自有边界，官方文档也不等于唯一最佳实践。
6. **评价维度仍需落地。** “从可维护性评审”给了检查方向，但还需说明哪些改动场景、证据和代价值得关心。审美等判断可以用对照样本与理由，不必编造数值指标。
7. **不要将用户“看懂了”变成学习档案。** 解释、应用、迁移和长期保持是不同证据；本方案不追踪或持久化这些状态。

这些修正与学习研究的方向相符：有组织的知识和适用条件比孤立事实更有助于理解与迁移，参见 [How People Learn 的综合结论](https://www.nationalacademies.org/read/9853/chapter/15)。[检索练习研究](https://doi.org/10.1126/science.1152408)支持主动回忆在其研究条件下对记忆的帮助，但不能据此证明本 skill 能提升真实用户的跨领域判断或 Agent 成品质量。下面的流程是设计方案，不是已获实验验证的教学定律。

## 完整使用流程

知识获取采用“模型内化知识建立候选结构 → 获取互补资料 → 按主张交叉检查 → 修订地图”。内化知识提供组织、解释和检索起点，不冒充可追溯文献；概览检查分支，规范校准定义，真实产物揭示决策，清单提供检查项，失败案例揭示条件和边界。资料可以确认原判断，不强迫制造观点反转。规则与停止条件见 [知识获取规则](references/sources.md)。

首次入门的交付顺序是：领域总览 → 八类地图 → 一个贯穿案例 → 后续导航。案例在首轮实际完成，展示约束从哪些条件和证据得来；后续再按兴趣加深。详细输出与验收规则集中在 [地图交付方式](references/map.md)，避免多处重复维护。

| 环节 | 用户怎样开始 | Agent 应交付什么 | 何时结束/转入下一步 |
|---|---|---|---|
| 定范围 | “我想了解摄影” | 范围、主要分支、默认视角与未覆盖部分 | 范围足以形成有用概览；不要求先选项目 |
| 看全景 | “给我 domain map” | 八类覆盖，各项用途与关系，必要来源 | 输出明确呈现八类、跨类关系及可继续展开的分支 |
| 连起来 | 首轮自动包含；后续可要求换案例或深入 | 同一具体对象的目标、检查、概念选择、产物、评价与返工 | 看得见约束来自已知条件、观察证据或明确教学假设 |
| 深入理解 | “展开这一块，比较这两个概念” | 机制、区别、适用条件、反例与关键证据 | 当前疑问得到解释；不强制答题解锁 |
| 用于协作 | “将这个要求改写给 Agent” | 目标、约束、候选机制、验收办法、未知项 | 可直接交给另一个执行者 |
| 检查效果 | “看看这个结果是否达标” | 按要求核对证据，解释遗漏和取舍 | 对当前产物给出有依据的判断 |
| 可选保存 | “把地图存下来” | 地图、来源、案例、可复用任务说明 | 保存知识产物，不保存用户学习等级 |

流程允许跳转：已经熟悉领域的人可以直接比较概念或改写需求；入门地图交付包含上述四部分。练习是可选检验，不是完成整套流程的强制条件。

## 八类如何串起来

以“做一期访谈播客”为例，仅示意结构而非完整播客教程：

> 录制阶段操作人声信号与音轨（实体）；理解信号电平等概念，采集录音文件（产物）；剪辑与混音后做听检或相关测量（评价）；若出现失真、背景噪声等症状（失败模式），先定位来源再决定处理；交付时核对目标平台要求（标准/指南）。术语区为这些对象和动作提供可检索名称。

这段关系说明了“为什么需要认识这些词”。正式地图进一步区分具体机制、适用条件和来源，不能凭这一条路径代表整个领域。

## 推荐用法

首次：

本仓库是维护源，测试时明确指定本仓库 `skills/orient/SKILL.md`。安装版可直接使用下述名称调用；修改后需同步安装目录。

> 使用 $orient，给我建立【领域】的 domain map。我希望先看到全景：核心实体、核心概念、高频术语、工作流、常见产物、评价指标、失败模式、标准与框架。解释每项用途和相互关系，标出范围、来源与推荐阅读路径。没有具体项目也先给概览，不做学习进度记录。

继续时只需普通话：

- “沿一个典型案例把这张图串起来。”
- “A 和 B 有什么区别，什么情况下会选错？”
- “我说‘更专业一点’，对应哪些可观察问题？先别替我确定方案。”
- “把我的要求改成可以交给 Agent 的说明，附验收办法。”
- “给我一个反例，检查我是否误用了这个概念。”

本仓库的 SKILL.md 是可复用规则，references 是按需执行细节；本设计文档是给人阅读的解释，不需要每次调用装载。

## 如何验证价值

知识获取流程的本轮测试见 [来源复测报告](evals/SOURCES-RETEST.md)，包含原始输出、引用修订、离线测试和未通过项。

地图组织方式的最新复测见 [输出与评估记录](evals/FLOW-RETEST.md)，其中保留 UI 与播客各轮原文、发现的问题和验证局限。

分别验证三个问题，不能相互替代：

1. 地图质量：八类有实质覆盖，核心条目有用途与关系，边界明确，来源支持主张，不把流派偏好伪装为统一规范。
2. 使用可行性：只给领域名也能交付，不强迫补项目/考试，不建立学习档案；单独翻译需求时不会展开无关课程。
3. 实际收益：真实用户能否更快找出值得问的问题、更准确地区分方案；Agent 结果是否在同一验收标准下改善。

子 agent 前向测试能检查前两类并发现失败，不能证明第三类。可重复输入和可观察条件见 [测试案例](evals/cases.md)。后续真实试用可保留同一任务的“原始表达”“详细普通话”“语义相同的术语版”三个条件，用同一模型与上下文生成结果，隐藏版本并打乱呈现顺序，让评审按预定标准检查重要遗漏、额外假设和可验收性。用多个任务或重复生成观察波动。详细普通话与术语版的比较，才有助于隔离术语本身的贡献。少数案例只能说明局部效果，不包装成普适提升百分比。
