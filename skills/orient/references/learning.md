# 学习与检验

## 筛选核心概念与安排理解顺序

用户接受地图末尾的邀请，或要求“挑核心词”“安排学习顺序”时，从已有地图筛选并排序，不重建整张地图，也不再追问选几个。用户指定数量或分支时遵从；未指定时按范围选择足以串起关键关系的一组，合并同义词，不固定为 30 个。

优先选择能支撑多个后续概念、帮助表达关键要求或避免重要误判的概念。每项给出：名称与简明含义、优先理解它的理由、所需先决概念（没有则说明可直接进入），以及它能帮助向 Agent 提出的一项具体要求或检查问题。可以用紧凑表格或分组呈现，不把每项展开成完整课程。

按理解依赖组织阅读顺序，并简述关键依赖为什么成立；区分真正先决条件与便于教学的建议顺序。知识关系仍可成网，相互依赖的概念可成组对照学习，独立分支可并列，不为生成 DAG 虚构单向依赖。

完成条件：用户能看出优先学什么、为什么这样排列，以及这些概念如何帮助表达或验收。最后推荐一个起点，用户愿意后再按下节展开；若用户已经要求开始讲解，则直接讲起点。序列是知识导航，不记录用户学到哪一步，也不据此判断掌握程度。

## 沿地图学概念

从用户选定的地图分支进入；没选时推荐一个能串起多个类别的代表性案例。先呈现具体问题，再解释机制和适用边界；与容易混淆的概念比较，最后让用户用于另一个例子。无需为每个词编造历史、发明者或“更先进替代品”。

展开后点明这个概念让用户能够更准确地提出哪项要求、补问哪个条件或识别哪种不合格结果。涉及一组相连概念时合并示范，避免学完只记住定义却不知道如何表达意图。

例如教学材料可按“现象 → 两种可能解释 → 如何区分 → 可选处理 → 如何验收”展开。仅当基础缺口确实妨碍理解时补基础，不强制先修完整底座。用户需要快速完成任务时，先交付，再提供练习。

## 检验的是能力，不是词汇记忆

互动检验默认一次提出一个问题并等待回答；用户要一组自测题时可批量给题，将参考答案分开。没有交互回复时不代替用户答题。练习应改变原例的一个关键条件，检验适用边界；背出术语不是必要条件。

按需要选择题型，不把它们当严格升级阶梯：

| 能力 | 可观察表现 |
|---|---|
| 解释 | 用自己的话说明机制及它解决的问题 |
| 区分 | 面对相似现象，指出还缺什么证据才能判断 |
| 表达 | 给执行者目标、约束与检查办法，避免擅自固定方案 |
| 判断 | 找出方案的隐藏假设，说明何时不应采用 |
| 迁移 | 换情境后仍能应用原则，并调整原来的要求 |

反馈先指出用户哪句话成立，再指出具体缺口和后果。错了就用一个更小的对照例子重讲，再换题；不要重复原题直到记住答案。两轮仍卡住时缩小目标或给带解释的示例，避免无限闯关。

反馈只针对这次回答：哪些判断成立、哪里还缺证据。新情境答对也不等于长期掌握。不保存答题记录、学习阶段或能力等级；用户以后想再检验时，重新给适合当时目标的情境。

## 时间预算

用户给 10 分钟：交付紧凑的八类地图与一条推荐路径，不通过删掉整类来缩短。给 1 小时：可用约 5 分钟定边界、15 分钟看地图及来源、15 分钟沿代表案例讲关键关系、10 分钟转成 Agent 任务并检查、10 分钟做迁移练习、5 分钟收尾。根据问题重分配；缺少用户回复或工具时间不能伪装为完成。

一小时的承诺是“获得领域初步导航，并在一个有限场景中试用”，不是掌握整个领域或拥有专家验收能力。
