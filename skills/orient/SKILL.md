# Orient

学习领域语言的首要目的，是让用户能把模糊意图压缩成 Agent 可执行、可验收的约束：准确指出对象、期望改变的维度、适用条件、限制和判断依据。

八类地图帮助用户发现尚不知道该问的问题，五层理解帮助用户把这些知识用于表达、选择和评价。地图是入门方式，这项表达能力是应用目标；没有具体任务也可以先建立全景。术语承载明确含义，准确的普通话同样合格。

## 八类覆盖与五层理解

八类回答“领域里有哪些内容”，五层回答“这些内容如何被理解和使用”。两者共同组织地图，不生成八乘五的重复表格，也不作为用户等级或先修关卡。

| 理解层次 | 回答的问题 | 在地图与展开中的落点 |
|---|---|---|
| Vocabulary 词汇 | 这个东西叫什么，如何检索和交流？ | 中文含义、标准术语、别名及使用语境 |
| Concept 概念 | 是什么，解决什么问题，为什么需要它？ | 地图说明用途；深入时解释机制、适用条件与反例 |
| Relations 关系 | 它依赖、影响或替代什么？看到 A 应检查什么？ | 条目给明确关系，并解释触发检查的条件，区分因果与相关 |
| Workflow 工作流 | 专业人士怎样把这些东西用于工作？ | 阶段、输入输出、决策点、反馈和返工，由代表案例串联 |
| Evaluation 评价 | 怎样判断结果好坏，依据是什么？ | 评价维度、观察或测量方法、取舍及验收证据 |

地图初版应让五层均可见；机制细节按需展开，不要求首次穷尽。检查是否只给了名字没有用途、只给了流程没有判断标准，或只列评价维度没有检查办法。

## 入口：先判断用户要哪种帮助

从当前消息和已有材料推断，不要求用户选择命令或重复背景。

| 意图 | 路径 | 当次完成条件 |
|---|---|---|
| “这个领域该知道什么”“建立 domain map”“带我入门” | 地图（默认） | 八类概览、问题与关系、建议阅读路径、来源和边界 |
| “深入讲这一块”“带我学” | 深入学习 | 所选概念的机制、对照案例与可选练习 |
| “怎么跟 Agent 说”“先帮我把需求说清楚” | 翻译 | 可复制的任务说明、验收方法、影响决策的未知项 |
| “考考我”“看看我有没有理解错” | 检验 | 一道新情境题；收到回答后给证据化反馈 |
| “帮我改页面/实现接口” | 执行任务为主 | 按原任务完成；仅在影响决策时解释术语 |

地图直接交付，不强制先访谈、先做项目或先通过考试。翻译也可单独进入，不以学完地图为前置条件。学习、检验的细节见 [references/learning.md](references/learning.md)，进入这些路径时读取。

同时要求全景与应用时，先交付地图，再完成指定应用；不让用户在已经明确要求的交付物之间二选一。只有明确要求翻译或执行时，才直接进入相应路径。

## 1. 确定地图范围

从用户信息确定领域、观察视角及深度。例如“摄影”可先给通用摄影概览；“金融”跨多个差异很大的子域，先展示子域边界，再用一个问题确认重点，或明确暂定范围。用户没给背景时用入门解释，不以探底题阻挡地图。

有实际产物、项目或任务时，用作地图中的例子和后续应用场景；没有时选有代表性的例子并标注。任务相关性用于标记重点，不用于删去其他重要分支。将用户目标、暂定假设、未覆盖范围区分开。

完成条件：明确地图涵盖什么、面向谁、哪些重要相邻领域暂不展开。无法澄清时也先交付有边界的概览。

## 2. 获取并校验领域知识

模型内化知识用于建立候选地图、解释概念、连接关系和提出检索问题；它不是可追溯的文献库，不能声称知道某句话来自哪份训练材料。外部资料用于补全、核实和挑战候选地图，用户材料用于限定当前场景。

建立新领域地图时，先读取 [references/sources.md](references/sources.md)，执行“候选结构 → 多类资料获取 → 按主张交叉检查 → 修订地图”。沿概览、规范/官方文档、真实专业产物、checklist、失败案例获取互补信息；不只寻找支持初稿的链接。已有可靠材料可以复用，单个术语解释或需求翻译只核查相关缺口，不机械执行完整调研。

## 3. 建八类全景地图

读取 [references/map.md](references/map.md)，首轮依次交付领域总览、八类地图、贯穿案例、后续导航。八类内容覆盖与五层理解贯穿其中；案例在首轮完成，导航用于继续深入。条目选择、关系解释、案例推演与交付检查以该文件为准。

用中文含义解释，附必要的标准术语/英文便于检索。相关、因果、先决条件、替代方案分别表述；知识关系可以成网，教学阅读路径才按依赖排序。地图是有边界的初版，不声称穷尽领域。

## 4. 从地图进入使用

地图交付后的默认衔接是邀请用户筛选核心概念并安排理解顺序，具体邀请见 map.md。用户接受邀请（如“继续”“可以”），或直接要求挑核心词/安排学习路径时，读取 [references/learning.md](references/learning.md) 的“筛选核心概念与安排理解顺序”并交付；若用户选了分支、翻译或其他任务，则按其选择继续。这些是可选后续，不是必须走完的关卡。

用户要学习时读 learning.md；用户要翻译需求时执行以下流程。

### 把模糊诉求变成可验收说明

先用普通话保留用户的真实目标，再补有帮助的术语。建议的成品结构如下，可合并成短段落：

> 为【使用者/场景】改善【对象及可观察问题】，期望【具体结果】。
> 遵守【已知限制和优先级】。先检查【待验证的原因】，根据证据选择做法。
> 用【检查步骤、样例或测量】验收，并覆盖【相关失败/边界情形】。
> 【未知项及其对方案的影响；必要时采用的暂定假设】。

不要为“显得专业”添加架构、工具、指标数值或冻结用户没要求冻结的设计。数值目标来自用户、标准或基线；否则标为待定或明确的建议。方案选择若有取舍，给出条件及建议，不把选项全部叠加。

尤其在没有实物的视觉需求中，“保持全部内容、功能或交互不变”也是新增约束，不能当作默认事实。若建议先做局部调整，将其明确写为暂定建议，并把允许改动的范围留作未知项。

交付时简短指出这次新增了哪些有效信息；若原话已经准确，直接确认并仅补真实缺口。复制出去的说明应自足，不能依赖“如上所述”。

完成条件：另一个执行者能理解目标、约束及如何检查结果；仍影响执行的未知项显式可见。证据不足时产物是诊断任务或条件化方案，而非假装确定的实施命令。

## 5. 根据用户意图闭环

- 只要完成任务说明：交付即可，可选附一个最有用概念的短解释。
- 要学习：解释后可邀请用新情境检验；用户愿意时再出题并等待真实回答。用户跳过则继续帮其做事，不推断掌握程度。
- 有 Agent 输出：对照原目标验收，指出具体缺陷与证据；不能以包含术语或遵循格式认定质量高。
- 要保存：按用户指定位置保存地图、来源、案例或任务说明这些知识产物。没有指定位置时可在当前工作区保存并告知路径；工具不可用则提供可复制内容。

产物合格与用户掌握分开报告。一次复述或一道题不能证明长期掌握；模型代答和模拟用户也不能作为用户学习证据。不建立学习进度、掌握等级或用户画像档案，不读取旧版学习档案来推断能力。后续从用户选择的知识材料继续，不在无关任务中自动纠偏。
