# 试写与装载后验收

验证围绕真实用途。自查试写、独立装载验收、用户评价三者分别记录，各自只证明自己那一层。

## 生成阶段的自查

准备与源语料不同题材的事实材料，固定需要保留的信息。试写一个文章片段和一个简短对话回应，用户只要一种用途时缩小范围；聊天任务给出前一话轮，看是否真正承接了对方。

先核对核心指导与原文方向一致：句长、出现次数等描述以实际核对为准，"原文末句展开较长"支持的是长句收束。再看迁移样例的命题是否变了：换了物件仍表达原文同一寓意的样例，回到方法与主题的区分重做。

然后按四项分别写具体观察：

| 项目 | 检查的问题 |
| --- | --- |
| 任务完成度 | 回答了当前问题吗？篇幅和格式适合任务吗？信息齐全吗？ |
| 内容保留 | 事实、数量、因果、条件、立场、确定程度是否原样保留？原作者的经历是否留在了原文里？ |
| 神韵 | 核心习惯有没有起作用？效果是否来自方法本身，而非原文词句、题材或固定模板？ |
| 自然程度 | 修辞、短句、收尾的强度是否与语料中的分布相合，像该作者本人会写的那样？聊天是否直接从对方的话接起？ |

问题定位到具体规则或样例，局部修订后复查受影响的用途。语料未覆盖的用途即使自查通过，仍保留迁移推断标记。是否喜欢由用户反馈确认。

## 使用阶段的验收

为生成物写 `evals/usage.md`，把以下四类任务换成适合本次核心习惯的新话题，每项写明装载方式；缺少独立运行条件时照样交付，状态记为未执行。

1. **跨题材写作：** 给定事实、读者和目的，写一篇完整短文，看开头、推进和收束能否共同形成目标神韵。源语料只有短文字时，长文适配的依据与不确定性单列。
2. **连续聊天：** 首轮为整个会话启用该风格，然后安排解释、追问和换题；后续话轮只发任务，看能否持续承接问题、保留核心气质、按情境调整修辞强度。
3. **范围与任务切换：** 同一会话中加入"这次只回答一句"等临时要求，下一轮回到普通交流，最后明确结束该风格。检查临时要求得到执行、会话偏好在其后仍适用、结束后用新的普通任务确认已停止。
4. **常驻护栏：** 以 output style 方式装载，发一个需要写代码或给出命令的任务，再发一个普通聊天。检查代码、命令、报错、路径、数字原样输出，只有周围的解释文字带风格；工程行为与默认样式一致；聊天话轮仍保有核心气质。

每项任务列清必须保留的事实、未知事项和允许展开的部分。建议和主观感受可以超出原文措辞；具体时间、人物动作、事件以材料为准，创作任务写明哪些部分允许虚构。

运行时目标 agent 只拿到生成的 `SKILL.md`、相关样例、装载请求和当前任务材料；原始语料、蒸馏对话、分析过程和预期答案留给评估环节。独立运行需要确实可用且获授权的新上下文。

先核对生成物确实被读取，再评价输出。装载失败修调用方式；核心气质淡，让目标描述更具体、改善样例或补充适用情境；表达僵硬，检查是否把一种手法写成了固定格式，放宽该处选择。

## 评价锚点

每个维度分别记"达到 / 部分达到 / 未达到 / 本题无法判断"，引用输出证据；四项各自成立才算通过，总分会掩盖事实问题。先列观察到的问题，再按下表定级。

| 维度 | 达到 | 部分达到 | 未达到 |
| --- | --- | --- | --- |
| 任务 | 所需信息、格式与当前话轮目的均满足 | 主要问题已答，仍有遗漏或篇幅失当 | 遗漏主要任务或违反明确格式要求 |
| 内容 | 给定事实及其确定程度保留，建议和假设能辨认 | 某处含混，分辨不出是感受还是新事实 | 出现与材料冲突或材料之外的具体断言 |
| 神韵 | 适用的表达选择有功能地形成目标感受，并随任务调整 | 只有表面标记，或与普通好回答难以区分 | 核心方向相反，或靠照搬原文主题制造相似 |
| 自然 | 表达强度与语料分布相合，读起来像该作者本人写的 | 局部超出或低于语料的强度，有套路感 | 为展示风格而堆砌，明显妨碍内容与交流 |

定级规则：出现材料之外的具体断言，内容项记未达到，其余事实正确也维持这一级；没有回答所问先记在任务项，内容项按实际断言另评；纯修辞且没有可核对事实时记本题无法判断。报时、原样输出这类任务主要检验格式与范围，神韵记本题无法判断。

"实际装载""任务与内容达标""符合目标感受""相对默认输出的变化""用户认可"分别报告。要判断风格贡献，用同模型、同任务、同宿主指令环境的无风格基线做匿名比较，允许平局；单次对照支持探索性结论，稳定效果需要在新的独立运行和不同任务上复现。

## 反馈进入下一版

先找用户指向的具体句子、段落或选择，再改对应规则。一次不喜欢的比喻，调整比喻的对象、密度或适用场景；用户明确要求全局禁用时记为用户偏好，并给出替代的表达方向。

用户可以拒绝所有候选。此时记录原句、情境和拒绝理由，重新定位表达方向；模型偏好的版本继续标为候选，用户认可后才成为正向样例。对刻意收尾的反馈，在同一任务里试写直接结束于有效信息或可执行动作的版本，再确认阅读感受；这个调整只作用于对应场景。

维护当前有效的规则、对应样例和简短修改依据。已解决的失误转写成正向指导：以后遇到同类情境怎样写。
