# 试写与装载后验收

验证围绕真实用途。一次自查可以发现明显问题，不能证明稳定性或用户偏好。记录实际做了什么，区分自查试写、独立生成对照和用户评价。

## 生成阶段的自查

准备与源语料不同题材的事实材料，固定需要保留的信息。试写一个文章片段和一个简短对话回应；用户只需要一种用途时相应缩小范围。聊天任务给出前一话轮，观察是否真正承接了对方。

按下面四项分别检查，并写具体观察：

| 项目 | 检查的问题 |
| --- | --- |
| 任务完成度 | 回答了当前问题吗？篇幅和格式适合任务吗？需要的信息是否齐全？ |
| 内容保留 | 是否改变事实、数量、因果、条件、立场或确定程度？是否带入原作者的经历？ |
| 神韵 | 已选核心习惯有没有发挥作用？效果是否依赖原文词句、题材或固定模板？ |
| 自然程度 | 是否为了展示风格强塞比喻、短句或收尾？聊天是否有不合情境的开头铺垫或说教？ |

将问题定位到规则或样例，局部修订后复查受影响的用途。语料未覆盖的用途即使自查通过，仍保留迁移推断标记。最终是否喜欢由用户反馈确认。

先核对核心指导与原文的方向是否一致，再评试写。句子长度、出现次数等描述需要实际核对；“原文末句展开较长”不能直接支持“以短句收束”的观察。迁移样例若仅把旧物换成另一个物件、继续表达原文的同一命题，应重新检查方法与主题的区分。

## 使用阶段的验收

为生成的风格 skill 编写 `evals/usage.md`，把以下任务换成适合本次核心习惯的新话题。没有独立运行条件时仍交付这些材料，状态记为未执行。

1. **跨题材写作：** 给出固定事实、读者和目的，写一篇完整短文，观察开头、正文推进和收束能否共同形成目标神韵。源语料只有短文字时，长文适配的依据与不确定性单列。
2. **连续聊天：** 首轮明确为整个会话启用该风格，然后安排解释、追问和换题。后续话轮不重复风格要求，观察能否持续承接问题、保留核心气质，并按情境调整修辞强度。
3. **范围与任务切换：** 在同一会话加入“这次只回答一句”等临时要求，下一轮回到普通交流；最后明确结束该风格。检查临时要求能得到执行、原会话偏好在其后仍适用、用户结束后能停止。

每项任务列清必须保留的事实、未知事项与允许的展开。建议和主观感受可以超出原文措辞；新增营业时刻、人物动作或事件不能仅凭“读起来合理”视为材料事实。创作任务明确哪些部分允许虚构。

只向目标 agent 提供生成的 `SKILL.md`、相关样例、装载请求及当前任务材料；运行时不提供原始语料、蒸馏对话、分析过程或预期答案。预期表现由评估环节读取。新上下文中的运行方式需要确实可用且已获授权，当前 agent 自称换一个角色不能满足这个条件。

先核对生成物实际被读取，再评价输出。装载失败应修复调用方式；核心气质不明显时，优先让目标描述更具体、改善样例或补充适用情境。表达僵硬时，检查是否把一种手法写成固定格式，放宽该处的选择。

验收按四个维度分别写证据。任务与内容是基础，神韵与自然程度也需各自成立：任务完成但气质不明、气质鲜明但强行表演，都需要修订。对适用的核心特征，指出实际文字如何形成预期感受；不以禁词次数、句长配额或一段文本的表面相似度代替判断。

每项记录实际输入、输出、运行环境、装载方式、评价及修订。行为结果跨多轮及不同任务成立后，才将对应用途记为装载后验收通过。用户未参与评价时，用户认可仍单独记为待确认。独立验收通过只覆盖测试过的环境和任务范围。

## 评价锚点与结论范围

每个维度分别记录“达到 / 部分达到 / 未达到 / 本题无法判断”并引用输出证据，避免用一个总分抵消事实问题。

先列出观察到的问题，再按下表确定等级。已明确识别出未经支持的具体断言时，内容项归为未达到；其余事实正确不能把该项升为部分达到。没有回答所问首先记在任务项，内容项按实际作出的事实断言另评；纯修辞没有可核对事实时可记为本题无法判断。

| 维度 | 达到 | 部分达到 | 未达到 |
| --- | --- | --- | --- |
| 任务 | 所需信息、格式与当前话轮目的均满足 | 主要问题已答，仍有遗漏或篇幅不合 | 遗漏主要任务或违反明确格式要求 |
| 内容 | 给定事实及其确定程度保留，建议和假设能辨认 | 某处含混，无法确认是感受还是新事实 | 出现与材料冲突或未经支持的具体断言 |
| 神韵 | 适用的表达选择有功能地形成目标感受，并随任务调整 | 只有表面标记，或效果与普通好回答难以区分 | 核心方向相反，或靠照搬原文主题制造相似 |
| 自然 | 表达强度与情境相合，读者无需知道skill也能顺畅阅读 | 有局部刻意、冗余或套路感 | 强行表演明显妨碍内容与交流 |

简单报时、原样输出等任务主要检验格式与范围，神韵可以记为本题无法判断。结束风格时回复 `OK` 只验证当轮格式；需要判断结束后的表现，应继续发新的普通任务，且不要仅凭共通写法仍在出现就断定风格未停止。

“实际装载”“任务与内容达标”“符合目标感受”“相对默认输出的变化”“用户认可”分别报告。要判断生成物的风格贡献，使用同模型、同任务、相同宿主指令环境的无风格基线，匿名比较并允许平局；绝对评价通过不足以证明存在增量。单次对照只支持探索性结论，声称稳定效果需要在新的独立运行与不同任务上复现。

## 需要对照实验时

用户希望比较提示策略、目标模型表现，或多次使用仍有偏差时，再做独立对照。使用相同任务、事实、模型版本、参数和已有指令环境，各条件分别在新上下文中生成多次。记录无法控制的差异。没有可用的独立运行工具时，提供可运行的实验材料并标记未执行；当前上下文中的角色扮演不算独立实验。

测试禁令效果可以比较：无风格指导、仅禁令、仅正向指导、正向指导加样例、正向指导加样例与少量禁令。优先围绕实际争议做最小对照。

正反措辞比较尽量表达相同的可检验要求，例如“全部使用小写字母”与“不使用大写字母”。“不要有 AI 味”与一份详细风格说明的信息量不同，这类结果只能评价整个方案，不能把差异全部归因于否定措辞。

隐藏条件名称并打乱输出顺序，请用户按四项标准比较；禁用词或句式的出现次数只作为辅助指标。模型自评仅供诊断，不能代替用户的阅读感受。

材料足够时，按整篇文档留出一部分语料检查候选特征的稳定性，避免同篇相邻片段分到两边。材料很少时使用新话题检验迁移，明确它无法独立验证作者风格的稳定性。

## 反馈如何进入下一版

先找用户指向的具体句子、段落或选择，再改相应规则。一次不喜欢的比喻可以调整比喻的对象、密度或适用场景；用户明确要求全局禁用时再记为禁用偏好。

用户可以拒绝所有候选。此时记录原句、具体情境及拒绝理由，重新定位表达方向；模型偏好的胜出版本不自动成为正向样例。用户尚未认可的新写法继续标为候选。对刻意收尾的反馈，可在同一任务中试写直接结束于有效信息或可执行动作的版本，再确认其阅读感受。这个试探只作用于相应场景，不外推成所有风格禁用修辞。

维护当前有效的规则、对应样例和简短修改依据。已经解决的失误无需持续堆成禁止清单；新的正向指导应能说明以后遇到同类情境怎样写。

## 维护蒸馏技能时

本技能的 [../evals/evals.json](../evals/evals.json) 提供带语料的行为测试案例。验证蒸馏流程时，在临时目录和独立上下文中运行请求，检查实际生成的文件与试写；预期结果留给评估环节。有 `usage_test` 的案例在生成后另开上下文，按给定话轮逐个发送，检验生成物的使用效果。案例文件本身不代表测试已执行。普通的风格提取任务无需运行这些案例。

需要复核已有测试与评分偏差时，阅读 [2026-09-11 Luna 运行报告](../evals/reports/2026-09-11-luna/report.md)。其中记录了生成、装载、匿名比较、用户拒绝两个候选及重跑中断的边界。

后续测试完成情况见 [补完报告](../evals/reports/2026-09-11-luna/completion-report.md)。复核评分规则时，可将 [calibration-inputs.json](../evals/calibration-inputs.json) 单独交给评审，再由检查者对照 [calibration-expected.json](../evals/calibration-expected.json)；预期文件不提供给被测评审。控制项只验证规则应用，不代表写作效果已通过。
