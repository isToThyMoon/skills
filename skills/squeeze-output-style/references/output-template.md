# 生成风格 skill

先有具体观察，再用这个结构组织产物。方括号是待填内容，完成的风格 skill 只留实际指令。

```text
[style-name]/
├── SKILL.md            目标 agent 使用风格时的直接指令
├── references/
│   ├── examples.md     校准写法的样例
│   └── evidence.md     复核与修订的依据
└── evals/
    └── usage.md        装载后验收任务
```

生成物独立可用：普通写作请求只依赖这个目录。

## 从观察到执行指令

每条核心观察改写为"情境 → 表达动作 → 可观察的效果"，直接面向使用该 skill 的 agent。例如证据支持"从具体细节切入"，写成"解释抽象关系时，从当前材料中选一个能体现该关系的细节，随后说明它与判断的联系"，对应检查是"细节是否帮助理解判断，是否取自当前材料"。

核心习惯按影响程度排序，贯穿输出的和情境合适才出现的分开说明。通过情境和样例说明取舍，让不同长度、题材的回答保有变化。用户明确要求的硬性偏好单独简短记录。

让"具体"随任务选载体：叙事用材料中的动作和物件，事实型说明用明确的范围、时间或条件。场景化开头等手法限定在材料与体裁合适的情境；事实稀少的说明文保留直接表达的空间。时间、地点、人物动作由当前材料支持，另作设定时先声明为假设或虚构。

## SKILL.md 骨架

```markdown
---
name: [style-name]
description: "以[核心表达特征]输出。用户指定[风格名称]写作或改写时应用；用户为当前会话启用此风格后，在后续聊天及写作话轮中持续应用，直到用户更改范围或风格。"
---

# [风格名称]

[一小段说明核心气质，以及读者感受由哪些表达选择共同形成。]

## 启用与持续应用

首次启用时读取本文件和 `references/examples.md` 中与当前用途相关的样例，从本次实际输出开始应用。用户要求某一篇文章时作用于该任务；用户要求本会话采用此风格时，在后续话轮持续应用，按用户后来的指令调整或结束。

风格作用于范围内的用户可见文字，包括解释、追问、进度说明和文章正文。引用、代码、数据及要求精确保留的文本遵循其内容要求。切换题材或任务类型时，依据新情境调整风格的表达方式。

上下文恢复后，若本会话仍有启用记录而核心指令已离开上下文，重新读取本文件和所需样例。新会话按其实际加载情况启用。

## 对话

## 内容与使用范围

根据当前任务提供的事实和立场表达，保留原有的因果关系、条件、数量及确定程度；具体时间、人物、动作、场景取自当前材料。篇幅、格式和必需信息按当前请求调整；使用范围遵循用户对任务或会话的约定。

从当前任务、读者关系和篇幅出发，沿适用的核心表达方向组织内容，借样例校准语气与节奏。对照期望的阅读感受，兼顾完整、准确和自然；发现具体偏差时局部调整。短回应保持轻量，长文关注整体推进与前后一致。直接交付当前请求需要的文字。
```

## references/examples.md

选少量互补例子，覆盖各核心习惯和两种用途。每例包含：

- **情境或任务：** 读者是谁、要传达什么、允许使用的事实。
- **文本：** 代表性短摘录，或依据给定事实构造的新文本。
- **注释：** 承担风格作用的具体词句、信息顺序或读者关系，以及为何适合这个情境。
- **来源标记：** 原文摘录写来源 ID 与位置；构造示例、改写、对话适配各自标明。

样例里的人名、数字、经历、比喻对象和标志性措辞属于该例的情境，新任务按当前材料另选。引用保留为必要的短摘录，构造示例标为构造。单一来源也可以围绕它支持的核心习惯构造多个情境的示例，证据仍记为那一个来源；模型生成的示例先标待验证，用户认可后记为偏好锚点。

跨题材样例用来检查方法是否脱离了原文主题：至少选一个落点不同的示例，沿用有证据的表达动作。叙事与事实型说明各校准一种写法。

## references/evidence.md

保留足以复核和修订的信息：

1. **材料范围：** 来源 ID、标题或文件、URL 或可定位段落、题材与体裁、已知读者、缺失情境。粘贴文本按段落编号保存必要摘录。
2. **八维观察：** 每维的候选特征或缺证说明；正文、引用、用户评价分开。
3. **采纳依据：** 观察、来源位置、可能作用、适用情境、证据强弱、生成指导，每条标明证据三源之一。
4. **取舍：** 进入核心、限定情境、待验证、本次搁置各有哪些；冲突如何处理。作者的具体观点和生平留在背景。
5. **验证状态：** 文件生成、自查试写、独立装载验收、用户认可各自的状态；实际运行环境、装载材料、任务、输出位置、发现的问题和对应修订。未执行的部分明确标出。

报告深度随材料规模调整；一小段语料用简短表格即可。每条核心指导可追溯。

## evals/usage.md

按 [evaluation.md](evaluation.md) 的使用阶段验收写可直接运行的任务，每项包含：装载请求、用户话轮或写作任务、固定事实、预期保留的核心习惯、达标标准。新话题与原文明显不同。期望表现供评估时使用，运行时只交给目标 agent 装载请求和任务材料。

默认覆盖一篇完整短文和一次"解释 → 追问 → 换题 → 临时更改输出要求 → 结束"的连续对话；用户只要一种用途时按实际范围调整。每个核心习惯至少在一个任务里可观察。写明任务尚未运行，或链接实际结果。

## 装载交付

给出两条使用实际风格名的可复制请求：

- 单次写作：`使用 $[style-name]，根据下面的材料写一篇……`
- 整个会话：`为当前会话启用 $[style-name]，后续聊天和写作都按它输出，直到我更改要求。`

目标环境支持技能调用时用其已有方式；只有文件读取能力时给出实际 `SKILL.md` 路径。文件已放进目录、出现在技能列表、被目标 agent 实际读取是三个状态，交付时如实写明当前到了哪一步。

## 生成后检查

- `name` 与目录名一致，小写字母、数字与连字符，长度小于 64；`description` 说明这个风格何时适用。
- 所有相对引用存在，模板字段已填完，核心正文能独立指导生成。
- 核心习惯与样例一致；构造样例和迁移推断标记清楚；未知内容保持为未知。
- 已有用户偏好保留；多来源规则在明确情境下共存。
- 启用范围、后续话轮的应用方式、质量标准已写入生成的 `SKILL.md`；验收任务覆盖选出的核心习惯，支持新上下文独立执行。
- 环境有技能校验器时运行，否则手动检查上述结构。校验器只检查结构，行为效果由第 5 步另记。
