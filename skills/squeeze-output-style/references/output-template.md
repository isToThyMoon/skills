# 生成风格 skill

先有具体观察，再使用此结构组织产物。方括号表示需要填入的内容；完成的风格 skill 应只留下实际指令。

```text
[style-name]/
├── SKILL.md
├── references/
│   ├── examples.md
│   └── evidence.md
└── evals/
    └── usage.md
```

`SKILL.md` 是目标 agent 使用风格时的直接指令，`examples.md` 帮助校准写法，`evidence.md` 支持复核与修订，`evals/usage.md` 用于检查装载后的实际表现。保持可独立使用；普通写作请求无需依赖本蒸馏技能或原始语料文件。

## 从画像到执行指令

将每条核心观察改写为“情境 → 表达动作 → 可观察的效果”，直接面向使用该 skill 的 agent。核心正文提供表达方向，样例展示这个方向如何成为文字，agent 根据当前内容决定具体写法。

例如，证据支持“倾向从具体细节切入”时，可写为“解释抽象关系时，从当前材料中选一个能体现该关系的细节，随后说明它与判断的联系”。对应检查是“细节是否帮助理解判断，是否取自当前材料”。具体动作以本次语料为准。

核心习惯按影响程度排序；有些贯穿输出，有些仅在情境合适时出现，分别说明。高标准体现在读者能持续感到核心气质，同时任务、内容和自然程度均达标。通过情境和样例说明取舍，让不同长度、题材的回答保有变化。用户明确要求的硬性偏好单独简短记录。

## 启用与持续应用

首次启用时读取本文件和 `references/examples.md` 中与当前用途相关的样例，从本次实际输出开始应用。用户要求某一篇文章时作用于该任务；用户要求本会话采用此风格时，在后续话轮持续应用，按用户后来的指令调整或结束。

风格作用于范围内的用户可见文字，包括解释、追问、进度说明和文章正文。引用、代码、数据及要求精确保留的文本遵循其内容要求。切换题材或任务类型时，依据新情境调整风格的表达方式。

骨架中的分节可以合并。文章与聊天的具体指导均应来自已选核心，避免复制一份与该风格无关的通用写作规范。若语料只支持简短文字，就按有限范围生成；未知的长文结构保持灵活。

## references/examples.md

选择少量互补例子，覆盖不同核心习惯及两种用途。每例包含：

- **情境或任务：** 读者是谁、要传达什么，列出例子允许使用的事实。
- **文本：** 代表性短摘录或依据给定事实构造的新文本。
- **注释：** 点出承担风格作用的具体词句、信息顺序或读者关系，说明为何适合这个情境。
- **来源标记：** 原文摘录写来源 ID 与位置；构造示例、改写、对话适配明确标注。

源文本的事实仅用于理解例子。样例中出现的人名、数字、经历、比喻对象和标志性措辞，在新任务中根据当前材料选择。引用保留为必要的短摘录；生成示例不得冒充原文证据。

只有一个来源时，也可以围绕它支持的核心习惯构造多个情境的示例；这属于覆盖用途，证据仍只有原来源。目标模型生成的示例先标为待验证，经用户认可后才记录为偏好锚点。

用跨题材样例检查方法是否脱离了原文主题。用户未要求继承原文命题时，至少选一个落点不同的示例，沿用有证据的表达动作；仅替换物件、继续复述同一寓意的样例不算跨题材检验。叙事与事实型说明各校准一种适用写法，避免后续输出为了营造场景补充事实。

## references/evidence.md

保留足以复核和修订的信息：

1. **材料范围：** 来源 ID、标题或文件、URL 或可定位段落、题材与体裁、已知读者、缺失情境。粘贴文本可按段落编号保存必要摘录及上下文摘要。
2. **八维观察：** 每维的候选特征，或缺证说明。正文、引用和用户评价的来源分开。
3. **采纳依据：** 观察、来源位置、可能作用、适用情境、证据强弱、生成指导。区分语料观察、迁移推断、用户偏好。
4. **取舍：** 哪些进入核心、只在特定情境使用、待验证或本次不采用；冲突如何处理。作者具体观点和生平留在背景中。
5. **验证状态：** 区分文件生成、自查试写、独立装载验收和用户认可。记录实际运行环境、装载材料、任务、输出位置、发现的问题及对应修订；未执行的部分明确标出。

报告深度随材料规模调整。一小段语料可以用简短表格完成，缺证维度合并列出。保持每条核心指导可追溯，不需要替每个形容词单独建档。

## evals/usage.md

按 [evaluation.md](evaluation.md) 中的装载后验收方式编写可直接运行的任务，每项包含：装载请求、用户话轮或写作任务、固定事实、预期保留的核心习惯、达标标准。新话题与原文区分，避免靠记住原文通过测试。期望表现供评估时使用，运行时只交给目标 agent 装载请求和任务材料。

默认覆盖一篇完整短文及一次“解释 → 追问 → 换题 → 临时更改输出要求”的连续对话；用户只需要一种用途时按实际范围调整。让适用的核心习惯都能在至少一个任务中被观察。写明任务尚未运行或链接实际结果。

## 装载交付

给出两条使用实际风格名的可复制请求，例如：

- 单次写作：`使用 $[style-name]，根据下面的材料写一篇……`
- 整个会话：`为当前会话启用 $[style-name]，后续聊天和写作都按它输出，直到我更改要求。`

目标环境支持技能调用时用其已有方式；只有文件读取能力时，提供实际 `SKILL.md` 路径，让 agent 读取核心正文和相关样例后应用。技能文件放进目录、出现在列表与被目标 agent 实际读取是不同状态，交付时如实说明。

## 生成后检查

- `name` 与目录名一致，使用小写字母、数字与连字符，长度小于 64；`description` 说明这个风格何时适用。
- 所有相对引用存在，模板字段已经填完，核心正文能够独立指导生成。
- 核心习惯与样例一致，构造样例和迁移推断的标记清楚，未知内容没有变成确定的作者特征。
- 已有用户偏好得到保留；多来源规则能在明确情境下共存。
- 启用范围、后续话轮的应用方式和具体质量标准已写入生成的 `SKILL.md`；验收任务覆盖这次选出的核心习惯，并支持新上下文独立执行。
- 环境有技能校验器时运行；没有时手动检查上述结构。校验器只检查结构，行为效果另行记录。
