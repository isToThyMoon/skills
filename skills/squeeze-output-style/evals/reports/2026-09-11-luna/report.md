# Luna 两阶段试跑

本文记录首次运行状态。中断的复测及新增案例现已完成，最新结论见 [补完报告](completion-report.md)；原始结论与记录保留供追溯。

本轮证明了“蒸馏生成 → 独立装载使用”能够执行，装载后也能出现可辨认的文风变化。但生成依据、事实保留和自然程度仍有失败，尚不能认定已达到用户期望的输出质量。

用户对本轮展示的两种收尾均评价为“有刻意感”。这一反馈高于模型在相应场景中的偏好排序；两个候选均不作为已获用户认可的样例。

## 运行范围

所有子agent均请求 `gpt-5.6-luna`，使用新上下文创建，未额外覆盖推理档位。运行处于当前宿主的共同指令环境，不等同于无系统提示的裸模型实验。主agent负责事实复核、结果归档及技能修订。

| 工作 | 实际完成 |
| --- | --- |
| 第一版生成 | 单段叙述、混合来源各一次，分别生成独立风格skill |
| 第一版使用 | 叙述风格七轮连续对话；混合风格一篇事实短文 |
| 默认对照 | 同模型无额外风格skill，运行相同七轮对话及相同事实短文 |
| 匿名评审 | 六对输出，各题独立打乱A/B，评审未读取条件映射 |
| 修订后生成 | 同一叙述案例由新agent重新生成一次 |
| 修订后使用 | 新agent完成前两轮；第三轮因使用额度限制失败，后续未运行 |

共完成三次生成、十八条实际使用回答。多轮对话是相关的一条轨迹，不能按每轮计算独立成功率。没有进行完整的重复采样或跨模型比较。所有语料来自本技能的构造测试案例，并非用户提供的真实作者语料。

归档时，本技能及三个生成物均通过技能格式校验；本技能的元数据、Markdown引用、JSON与空白检查通过。这些检查不代替上面的行为评价。

生成agent只得到技能快照和案例请求，未提供预期结果；使用agent只获准读取生成的核心正文与样例，逐轮接收实际任务；原始语料、证据文件及eval答案不提供给使用阶段。生成目录与使用输出保存在隔离目录，归档见 [artifacts.json](artifacts.json)。

## 生成阶段发现

**结构成立，内容依据仍有偏差。** 第一版两个生成物都包含核心正文、样例、证据与使用任务，相对引用可解析，且明确写出独立装载尚未验证。

单段叙述的第一版把“短促收束”列为核心习惯，证据文件同时描述末句较长。按句号分句、去掉标点，原文四句分别为21、17、6、28字，末句最长。这足以说明该规则与所宣称的观察方向不一致；它可以作为另一种设计选择，但没有被这样标注。

第一版样例多次重复“旧物暂时留下，等以后派上用场”的落点：拉头、长椅上的照料、抽屉里的电池分别承担相近寓意。跨题材迁移在部分例子中退化成主题改写。

修订后生成物补入了事实型说明，但叙事样例仍将旧拉头换为缺齿钥匙，继续以暂时保留收束；并在“只使用给定事实”的示例中加入了未给出的“试着转了转，当然打不开”。这说明增加指导后，问题仍未充分解决。当前保留真实结果，未将重跑标为修复通过。

## 使用阶段发现

**装载版有变化，但变化与质量分别判断。** 第一次旧物整理回答中，默认版使用分类清单，装载版使用连贯段落并更多地把物件与情感相连。后续追问、报时和返回整理任务都能继续回答，临时要求“只回复时间”得到执行。

**事实边界失守。** 介绍阅览室的任务只给出“周三开始试营业、每晚至八点、试行两周”。装载版开头写成“周三傍晚”，另添“第一次和大家见面”；首开时刻并无材料依据。按本轮修订后的事实标准，新增具体时间导致内容项未达标。默认版也有“本周三”与将使用反馈用于后续安排等材料未明确支持的表述；该问题并非装载风格独有。

**主题与动作增补仍需复核。** 银杏叶短文中，装载版增加“落在桌上、捡起来、放在一旁、暂时没有丢掉”，又以“也许有些来处，并不急着被想起”收尾。这与来源的保留旧物主题接近。原测试对创作余量的规定有歧义，因此记录为内容边界与迁移风险，不把所有新动作直接计作确定违规。后续eval已明确具体人物、动作和场景仅限给定材料，感受可以展开。

**混合风格增量有限。** 装载版和默认版都保留三个小组、两周、两组愿意继续、一组反馈费时、尚未量化时间效果，并建议继续小范围验证。装载版更短，但这不足以证明稳定的风格贡献；该任务也不适合单独判断画面感是否迁移成功。

**范围测试的结论有限。** 七轮中的报时和原样输出 `OK` 成功。最后一轮之后没有再发任务，因此这次运行没有验证结束风格后的持续状态。

## 匿名评审与人工复核

Luna匿名评审在六对文字中偏好装载版五对，偏好默认版一对。这是单个评审对六组相关任务的主观排序，不能作为通过率或稳定胜率。

主agent复核发现两处重要评分错误：评审把“周三傍晚”当作完整保留原事实，并用“聊天短一点”的偏好给文章长度扣分。提示复核后，评审承认两处边界问题；但其对新增具体时刻仍给“部分达到”，与新锚点中的“未经支持的具体断言 → 未达到”不完全一致。本报告按更明确的事实锚点裁定该项未达标，保留原评审与复核版供追溯。

eval设计审查本身也出现一次误读：最初认为源文没有师傅话语。原文实际有“说以后也许用得上”的转述。复核后修正为“台词”一词不够精确，改称“转述话语”；对话证据不足的判断仍成立。

## 用户校准

用户看到的两句为：

> A：先清出空间，也给有情感分量的东西留出从容决定的时间。

> B：盒子也不必继续替所有犹豫占地方。

A来自默认版的回归整理回答，B来自装载版的追问回答。它们来自不同话轮，这次提问只用于收尾感觉的校准，不作为同任务A/B实验。用户明确反馈：**“两句都有刻意感。”**

模型此前把两句所在回答的自然程度均评为达到，说明它的判断不足以代表用户阅读感受。这个反馈仅适用于当前整理建议的收尾，不推断用户在全部文章中排斥修辞，也不把另一个未经认可的候选记为已确认。

可以进一步试写直接结束于有效动作的候选，例如“先处理坏线。螺丝收进工具盒，便条单独放好。”这条为主agent提出的新候选，尚未获得用户认可，也未做独立运行。

## 已落实的修订

- 核心规则反向核对支撑原句，区分观察与另作的迁移选择；小样本允许只提取两条方向。
- 样例跨题材时检查命题是否变化，给事实型说明保留直接使用范围、时间和条件的写法。
- eval补充生成检查、逐轮事实边界、适用特征、默认对照和四维评价锚点；第三个案例补入使用阶段任务。
- 分开记录装载、任务与内容、神韵、相对默认版的变化及用户认可。
- 用户可以拒绝所有候选，模型胜出的版本不会自动成为正向样例；收尾反馈在相应情境中校准。

修订后的使用阶段只完成前两轮，第三轮触发额度限制。最新逐轮eval新增任务、用户校准后的指导和剩余重跑均未独立验证。

## 这轮如何使用Luna

Luna适合承担这次生成与使用试跑，已经帮助暴露具体问题。当前证据不支持让它独立裁定高标准是否达成：生成样例存在未核实的推断，评审会漏判事实并误用偏好。后续应优先补入用户真正认可的正向语料、完成剩余装载测试，并保留人工事实复核与用户阅读反馈。
