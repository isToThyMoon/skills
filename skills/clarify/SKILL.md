# Clarify

把 natural-language intuition 转成 domain-language representation：保留用户真正想要的结果，借助领域概念区分解释、暴露假设，再形成可执行、可验收的要求。专业语言是澄清的结果，不是替用户预选的答案；准确普通话同样合格。

## 进入与分流

从用户原话和已有材料开始，不要求先建立领域地图或提供项目。只有命令没有内容时，邀请用户给一句想说清楚的话。用户要全景入门而非澄清具体诉求时，可建议使用 orient；本流程不依赖其他 skill 才能完成。

用户要求讨论时进入短循环；要求“直接整理、别追问”时直接交付条件化版本，标出真正影响执行的未知项。原话已准确时只补真实缺口。用户改变话题或结束时尊重其选择。

## 澄清循环

1. **保留意图。** 简短复述想改善的对象和结果，区分用户偏好、观察、原因猜测与提出的方案。有材料先检查相关部分，不反问材料已能回答的事情。
2. **拆开解释。** 对最关键歧义给少量不同解释，用普通话说明区别，必要时附领域术语。它们是候选而非已确认诊断；允许用户指出“都不是”。
3. **问能改变判断的问题。** 默认每轮一个核心问题，必要时合并紧密相关的问题。围绕目标、可观察现象、使用场景、取舍或限制追问，说明答案会改变什么。借鉴 grill 对假设和矛盾的检查，但不盘问、不迫使用户证明审美偏好，不机械填问卷。
4. **更新描述。** 根据真实回答收窄解释，简短呈现“你的意思更接近……，因为……”。只有确有歧义才请求确认；回答已清楚时不重复确认。用户纠正时更新，不维护最初猜测。

每次提问后等待用户回答，不模拟其选择，也不预先展开整套问题树。用户不知道时提供具体对照或说明需要什么证据；无法获得时保留未知，给条件化描述。

当目标、对象和关键区别已清楚，剩余未知不再改变主要方向时收束。若缺少实物使诊断无法成立，交付检查任务，不无限追问或硬凑实施方案。

## 领域知识怎样参与

用模型内化知识提出候选解释、相关概念与检索问题。对不熟悉、时效敏感、争议或高风险的领域判断，查原始规范、官方文档、研究或真实专业产物；只查当前歧义需要的内容，不把短讨论扩大为完整领域调研。用户禁止联网时明确未核查边界。

让术语连到观察或问题：它指什么、为什么适用于当前表达、什么证据能区分其他解释。材料中的建议不自动成为用户限制；不为显得专业增加技术方案、量化指标或未经确认的改动范围。来源中的事实、综合判断、用户确认和教学假设分别表述。

## 收束交付

根据复杂度简短交付两部分：

**领域化问题描述**：保留原始目标，用准确概念表达已澄清的问题；说明关键术语与原话的对应关系，并区分已知现象与待验证原因。主观偏好可保留为偏好，不必伪装成行业标准。

**给 Agent 的任务说明**：自足地写出对象与场景、期望结果、已知限制和优先级、应检查或修改的方向、验收依据，以及仍影响方案的未知项。数值来自用户、标准或基线，否则待定或明确标为建议。若用户只要问题描述，则不额外扩成实施任务；有了任务说明也不自动执行修改。

完成检查：用户原意是否保留？新增约束有无依据？候选原因是否被误写成事实？执行者能否知道做什么、如何检查，以及哪些信息还不能确定？不按术语数量判断质量，不建立学习进度、掌握等级或用户画像。

## 交互示例

用户：“这个页面很乱。”

可以问：“你说的乱，更接近不知道先看哪里、分不清内容分组，还是找目标时要扫过太多内容？也可以用自己的话描述。”

若用户说“不知道先看哪里”，下一步优先问页面最重要的任务，而不是直接要求删除内容。只有材料支持时，才将问题收窄为视觉层级与任务优先级不匹配；没有实物时，把这个关系写成待验证假设。该示例展示澄清方式，不作为所有领域的问卷模板。
